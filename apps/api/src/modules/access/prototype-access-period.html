Вопрос (спека #48, H4). Администратор прекращает доступ Анны к платформе. Модуль Сотрудники делает это сразу и синхронно. Последствия (завершить участие Анны в проектах в модуле Доступ, отозвать её подключения агентов в модуле Подключения агентов) приходят событиями через outbox, RabbitMQ и inbox: с задержкой, повторно и не по порядку. Доступ не может синхронно спросить Сотрудников, Подключения агентов не вызывают никого. На каждый запрос входной слой спрашивает Сотрудников про учётную запись вызывающего, затем Подключения агентов (подключение действует?), затем Доступ (разрешения), и передаёт данные учётной записи в контексте запроса. Какое правило даёт пять принятых исходов при любом порядке доставки событий?

Правило

Переключение правила переигрывает те же действия заново, так что один и тот же сценарий можно сравнить между правилами.

    Сценарии по шагам

    Проверка всех порядков

    Перебираем все чередования небольших сценариев: действия администраторов по порядку, а доставку каждого события в модуль в любой момент после его появления, в любом порядке, с повторной доставкой. После каждого шага спрашиваем входной слой про каждую запись Анны (это и есть «запрос в каждой точке») и сравниваем с тем, что требуют исходы 1–5. «Призрак»: после доставки всех событий запись хранится действующей, но входной слой её не пропускает.
