# Как платформы поддерживают работу команды с агентами

В таблице собраны примеры из документации пяти продуктов и протокола A2A. В последней колонке предложены учебные сценарии для магазина из брифа.

| Продукт или протокол | Что делает сервер | Что проверить на занятии |
|---|---|---|
| Linear | Когда сотрудник поручает агенту задачу, Linear создаёт сессию и отправляет исполнителю вебхук с описанием задачи, обсуждением и инструкциями команды. Когда агент запрашивает уточнение, Linear показывает статус ожидания. Ответ сотрудника приходит исполнителю в той же сессии. [Протокол сессий Linear](https://linear.app/developers/agent-interaction) | Агент спрашивает, в какой момент отправить письмо о возврате. Менеджер отвечает в задаче. В истории одной сессии видны вопрос, ответ и итог работы. |
| Paperclip | Перед работой агент запрашивает задачу через `checkout`. Повторный запрос её владельца проходит успешно. Если задача уже принадлежит другому агенту, сервер отвечает `409 Conflict`. [Протокол Paperclip, шаг 5](https://docs.paperclip.ing/guides/projects-workflow/routines/#5-checkout) | Два исполнителя пытаются забрать задачу по уведомлениям. Один приступает к работе, второй получает отказ. Владелец повторяет запрос после потери ответа и сохраняет задачу за собой. |
| Amazon Bedrock AgentCore Gateway | При каждом вызове шлюз может запустить функцию, которая проверяет права на инструмент или операцию MCP до обращения к целевому сервису. Отдельная функция может обработать ответ перед отправкой клиенту. [Обработчики запросов и ответов AWS](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-interceptors.html) | Агент читает документ о возвратах. Администратор отзывает у сотрудника доступ. При повторном чтении обработчик сверяется с актуальными правами и отклоняет запрос до вызова хранилища. |
| Langfuse | Команда хранит вопросы с ожидаемыми ответами и сравнивает несколько прогонов на одних примерах. Для отдельного вопроса видны ответ модели, оценка и запись вызова с задержкой, числом токенов и стоимостью. [Эксперименты на одном наборе данных](https://langfuse.com/docs/evaluation/get-started/offline) | Команда меняет инструкцию помощника и повторяет вопросы о возвратах. Для ответа с неверной ссылкой студенты сравнивают выданный адрес с эталоном и открывают оба прогона. |
| Glean | Каталог показывает сотруднику агентов, которых он может запускать. Поиск находит агента по названию или назначению. В карточке видны автор и отметка о проверке командой. [Каталог агентов Glean](https://docs.glean.com/agents/concepts/agent-library) | Сотрудник поддержки находит агента по запросу «проверить возврат» и запускает его. Коллега без доступа вводит тот же запрос и видит другой список. |
| A2A | Удалённый агент публикует карточку с навыками, адресом сервиса и требованиями к аутентификации. Клиент может отправить поручение, получить идентификатор задачи, проверить её состояние и забрать результат. [Карточки, задачи и результаты в A2A](https://a2a-protocol.org/latest/topics/key-concepts/) | Агент заказов читает карточку агента уведомлений и просит проверить обработку события возврата. По идентификатору задачи он получает отчёт с результатом теста. |
