# Живая доска EventStorming для разговора с агентом

Проверено 12 ноября 2026 года по официальной документации и исходникам. Это исследование инструментов, без установки, создания досок и проверки подключений на реальном аккаунте. Оно не меняет состав [первой версии платформы](../first-version.md).

## Что выбрать

Кирилл предпочёл локальную страницу или Excalidraw. Для этого направления есть два пути. Быстрая проба готового интерфейса возможна через официальный Excalidraw MCP App, если клиент поддерживает MCP Apps и передачу ручных правок. Постоянную локальную доску можно построить на Excalidraw SDK с сохранением JSON и небольшим мостом к агенту. Второй путь требует отдельной разработки. Excalidraw+ остаётся облачной альтернативой с готовым API. Это рекомендации по документации, без испытания в текущем клиенте.

Главное условие выбора: после твоей ручной правки агент должен прочитать актуальную доску и изменить несколько существующих карточек. Красивая картинка, встроенная генерация из текста и экспорт диаграммы сами по себе этого не доказывают. Необходимы постоянные идентификаторы элементов, обратное чтение, сохранение между разговорами и способ восстановить ошибочную правку.

| Вариант | Что документировано | Что потребуется |
| --- | --- | --- |
| Miro | Чтение доски, создание элементов, применение изменений, удаление; история доски | Аккаунт, доступ к доске, OAuth, доступный набор MCP-инструментов |
| FigJam | Чтение дерева с ID, создание, изменение и удаление стикеров и связей через `use_figma` | Поддерживаемый клиент, удалённый MCP, нужные права аккаунта |
| Excalidraw+ | Чтение сцены, добавление, изменение и удаление элементов по ID | Подписка Plus с доступом к API, ключ с правом записи; API/MCP в beta |
| Excalidraw MCP App | Редактор внутри чата, ручные правки, продолжение из checkpoint | Клиент с MCP Apps; отдельно проверить долговечность состояния |
| Excalidraw SDK / tldraw SDK | Программное управление редактором | Разработка приложения и связи с агентом, сохранение и синхронизация |
| HTML в Orca | Можно показать интерактивную страницу в чате | Для общей изменяемой доски нужен отдельный путь обмена состоянием |

Таблица суммирует источники из следующих разделов. Последняя строка основана на проверенных ограничениях локального механизма Orca, а не на обещании готовой интеграции.

## Excalidraw: три разных предложения

### Excalidraw+ с сохранённой сценой

У платного Excalidraw+ есть официальный MCP `https://api.excalidraw.com/api/v1/mcp` поверх публичного API. Документация прямо отделяет его от открытого MCP App. Подключение использует Streamable HTTP и API key в Bearer-заголовке. API и MCP находятся в public beta: имена инструментов и схемы могут меняться. [Описание MCP](https://plus.excalidraw.com/docs/mcp).

Для совместной работы есть `get_scene_content`, поиск по содержимому и `edit_scene_content`. Последний добавляет, меняет и удаляет элементы. Новые элементы получают постоянные ID; последующие изменения ссылаются на них. Есть стикеры и стрелки, привязанные к элементам. Это позволяет вести одну сцену по ходу разговора. [Инструменты MCP](https://plus.excalidraw.com/docs/mcp/tools).

Важная граница: повторная генерация через `replaceDiagramId` заменяет диаграмму и отбрасывает ручные изменения внутри неё. Поэтому для живой доски лучше точечные операции над элементами. У генераторов описана ошибка конфликта при изменении сцены во время расчёта, после которой надо прочитать состояние и повторить запрос. Это не доказательство одинаковой защиты всех операций от одновременной записи. [Описание изменения диаграмм](https://plus.excalidraw.com/docs/mcp/tools).

Ключ ограничен workspace и разрешёнными API-маршрутами; ключ только для чтения не открывает инструменты записи. Тариф Plus включает облачное сохранение сцен, совместную работу и MCP/API. Лимит встроенных AI-запросов нельзя автоматически считать лимитом внешнего агента через MCP. Поведение undo после API-операций и восстановление истории надо проверить в пробной сессии. [Права ключей](https://plus.excalidraw.com/docs/mcp/auth-and-permissions), [состав подписки](https://plus.excalidraw.com/pricing).

### Открытый Excalidraw MCP App

Официальный `excalidraw/excalidraw-mcp` показывает редактируемый Excalidraw прямо в чате с поддержкой MCP Apps. Есть готовый удалённый endpoint `https://mcp.excalidraw.com`, локальный вариант и лицензия MIT. Это готовый интерфейс для разговора, но не тот же продукт, что облачное рабочее пространство Plus. [Репозиторий MCP App](https://github.com/excalidraw/excalidraw-mcp).

В исходниках `create_view` возвращает checkpoint; продолжение может восстановить его, добавить или удалить элементы. Редактор сохраняет ручные изменения в checkpoint, а агенту предписано сначала прочитать контекст виджета. Значит, это не только одноразовая генерация картинки. Однако работа обратного чтения зависит от поддержки протокола клиентом. [Реализация сервера](https://github.com/excalidraw/excalidraw-mcp/blob/main/src/server.ts).

Checkpoint нельзя без проверки принимать за постоянное хранилище проекта. В реализации есть память процесса, временные файлы и Redis с TTL 30 дней; выбор зависит от развёртывания. Для переноса между сессиями нужен экспорт и проверка повторного открытия. [Хранилище checkpoint](https://github.com/excalidraw/excalidraw-mcp/blob/main/src/checkpoint-store.ts).

### Открытый редактор и SDK

У Excalidraw есть редактируемый формат `.excalidraw` в JSON и экспорт. Файл можно хранить в Git, сохраняя саму доску, а не только изображение. [Возможности проекта](https://github.com/excalidraw/excalidraw).

SDK предоставляет `getSceneElements`, `updateScene`, `onChange` и управление попаданием изменений в историю. Из этого можно собрать локальную страницу, где человек и агент работают с одним документом. Но SDK не включает готовую совместную работу. Сохранение, связь с агентом и разрешение конфликтов становятся нашей разработкой. Локальное хранение JSON также не исключает передачу прочитанного содержимого внешней модели. [API редактора](https://plus.excalidraw.com/docs/sdk/excalidraw/api/props/excalidraw-api), [FAQ о collaboration](https://plus.excalidraw.com/docs/sdk/excalidraw/faq).

## Miro

Miro предлагает официальный удалённый MCP по адресу `https://mcp.miro.com`. FAQ описывает OAuth 2.1, работу в пределах текущих прав пользователя и выбор одной команды при авторизации. MCP умеет читать содержимое и создавать или изменять стикеры, рамки, фигуры и другие объекты. Для нового разговора достаточно сохранить ссылку на доску, но доступ и авторизация должны оставаться действительными. [Официальный FAQ](https://developers.miro.com/docs/miro-mcp-server-frequently-asked-questions).

Для живой работы существенна новая группа `canvas_*`. `canvas_read_as_svg` читает элементы, `canvas_create_from_svg` создаёт их, `canvas_update_from_svg` применяет разницу к доске. Это SVG-представление объектов, а не вставка одной картинки. Формат поддерживает стикеры, рамки и связи. Предыдущие `layout_*` объявлены устаревающими. Документация предлагает использовать возвращённый `result_svg` для следующих операций. Удаление требует явного согласия; ошибочно удалённое можно восстановить через историю доски. Чтение можно ограничить рамкой, чтобы не отправлять агенту сотни лишних объектов. [Изменение canvas tools](https://developers.miro.com/changelog/canvas-tools-replace-layout-tools).

Свежая страница лимитов указывает 100 вызовов MCP в день на Free, 500 на Starter, 2 000 на Business и 10 000 на Enterprise. Сброс происходит в 00:00 UTC. Вызовы чтения тоже расходуют лимит; это отдельная величина от AI-кредитов. [Лимиты MCP](https://developers.miro.com/docs/mcp-usage-and-daily-limits).

В официальных материалах есть расхождения. Старая сравнительная таблица ещё говорит «Enterprise only», FAQ и свежие лимиты перечисляют все планы. Более ранний changelog ограничивал расширенные инструменты тарифами вне Enterprise. Поэтому нельзя заранее обещать одинаковый набор операций любому аккаунту. После подключения надо проверить фактические tools и права команды. [Сравнение MCP и REST](https://developers.miro.com/docs/mcp-server-vs-rest-api), [раннее расширение инструментов](https://developers.miro.com/changelog/new-miro-mcp-server-tools-create-items-boards-code-widgets-read-comments-and-more).

REST API остаётся отдельным путём для интеграции через код. Он покрывает стикеры, рамки, фигуры и connectors; MCP предоставляет более крупные операции для разговора. Наличие REST API не означает, что нужный метод уже доступен агенту как MCP tool. Для EventStorming у Miro есть готовый шаблон. Это полезная заготовка доски, но правила проведения сессии и смысл цветов всё равно задаёт ведущий. [Сравнение интерфейсов](https://developers.miro.com/docs/mcp-server-vs-rest-api), [шаблон Event Storming](https://miro.com/templates/event-storming-template/).

## FigJam

Утверждение «официальный Figma MCP только читает» уже неверно. Текущая документация перечисляет `use_figma` для создания, изменения, удаления и инспекции содержимого FigJam, включая стикеры, sections и connectors. `generate_diagram` отдельно создаёт диаграммы. Возможности генерации и точечного изменения здесь надо различать. [Официальные инструменты](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/).

Официальный скилл `figma-use-figjam` указывает `get_figjam` как способ получить XML-дерево с ID для следующих вызовов `use_figma`. Это подтверждает нужную связку «прочитать ручную правку, затем изменить выбранный объект». [Скилл FigJam](https://github.com/figma/mcp-server-guide/blob/main/skills/figma-use-figjam/SKILL.md).

Запись доступна через удалённый сервер и поддерживаемый клиент. FAQ описывает beta, ограничения мест записи для разных seats и будущую оплату по использованию. Поддержку именно нашего клиента и права конкретной доски надо выяснить после подключения; доступность генерации не доказывает доступность `use_figma`. Историю и undo агентских операций тоже нужно испытать. [FAQ Figma MCP](https://help.figma.com/hc/en-us/articles/39252411778583-Figma-MCP-server-FAQs).

В каталоге этой сессии найден неустановленный Figma-плагин с описанием генерации FigJam. Поиски Miro и Excalidraw не вернули плагинов. Это результат конкретного каталога, а не отсутствие MCP у этих продуктов. Ничего не установлено; набор tools после подключения неизвестен.

## tldraw и локальная страница

Agent starter kit tldraw уже демонстрирует чат рядом с холстом. Его агент читает скриншоты и структурированные фигуры, учитывает действия пользователя, создаёт, меняет и удаляет элементы по мере ответа. Это близкий образец нужного взаимодействия. Но starter kit является основой своего приложения с ключами провайдеров моделей, а не подключением текущего Codex к произвольной доске tldraw. [Agent starter kit](https://tldraw.dev/starter-kits/agent).

Для совместной работы есть отдельный multiplayer starter kit с WebSocket, Cloudflare Durable Objects, SQLite и R2 для файлов. Соединение его с агентом, права, эксплуатация и перенос состояния остаются задачами разработки. [Multiplayer starter kit](https://tldraw.dev/starter-kits/multiplayer).

Лицензию SDK нельзя считать MIT только потому, что код стартовых примеров открыт. По стандартным условиям SDK разрешён для разработки; production требует действующего trial, commercial или hobby key. Коммерческое применение нужно оценивать по коммерческой лицензии. [Лицензирование tldraw](https://tldraw.dev/community/license).

HTML в Orca пригоден для быстрого показа схемы. В этой сессии доступен механизм inline HTML, но он не подтверждает общий изменяемый документ с обратной передачей ручных правок агенту. Его ограничения включают отсутствие сети и отдельный файл для новой публикации. Поэтому обещать из него готовую живую доску нельзя. Локальная страница с JSON и специальным мостом могла бы решить задачу, но это отдельный прототип. Эти сведения получены из локальных инструкций [orca-chat-visuals](/Applications/Orca.app/Contents/Resources/native-chat-visuals/skills/orca-chat-visuals/SKILL.md), прочитанных ведущим агентом.

## Предлагаемое устройство локальной доски

Это техническая гипотеза для отдельного прототипа. В браузере работает готовый редактор Excalidraw. Небольшой локальный процесс хранит один документ и предоставляет агенту чтение текущей сцены и изменения выбранных элементов. `onChange` передаёт ручные правки в это же хранилище; входящие изменения агента доходят до редактора через его API. Простое перезаписывание файла рядом с открытой вкладкой не создаёт такой обмен автоматически.

Мосту нужны постоянные ID, номер версии документа и отклонение записи по устаревшей версии. Агент меняет конкретные поля, а не отправляет старую сцену целиком. Изменения одного ответа желательно объединять в одну отменяемую операцию. JSON сохраняется атомарно, а снимки можно добавлять в Git после законченного этапа. Такое поведение надо реализовать и проверить; оно не предоставляется SDK в виде готового MCP.

Более простой вариант для первой ручной проверки: экспортировать `.excalidraw`, дать агенту изменить файл и импортировать обратно. Он позволяет оценить карточки и нотацию, но требует действий человека и не является живой синхронизацией. Для нового разговора нужен путь к документу и доступ к тому же локальному процессу. Полностью локальное выполнение модели является отдельным выбором, даже когда доска хранится на компьютере.

## Как вести EventStorming с агентом

Следующий порядок является предложением для нашей сессии, а не встроенной функцией выбранного сервиса.

1. Обсуждаем один сценарий и собираем события в прошедшем времени. Агент помечает собственные предположения как гипотезы.
2. Разделяем тип карточки и её статус. Например, оранжевый обозначает событие, синий команду; отдельная отметка показывает, подтверждена ли карточка владельцем. На доске остаётся легенда.
3. Перед записью агент читает актуальную рамку или сцену. После ручных правок человека прежнего состояния из переписки недостаточно.
4. Агент меняет только нужные объекты по сохранённым ID, добавляет связи и читает результат. Полную перегенерацию используем только по отдельной договорённости.
5. Ты видишь изменения и продолжаешь разговор или правишь доску руками. Спорные правила, альтернативы и вопросы остаются видимыми.
6. После подтверждения переносим решения в документы проекта, сохраняя ссылку на доску и снимок. Новая сессия получает адрес доски, нужную область и краткий журнал решений.

Доска хранит ход исследования. По правилам проекта термины живут в `GLOSSARY.md`, связи и инварианты в предметной модели, значимые архитектурные решения в ADR, а требования изменения и критерии приёмки в его GitHub issue. Стикер не становится требованием или разрешением на реализацию автоматически. Для SaaS рабочее состояние находится у сервиса; JSON в Git служит снимком, пока отдельно не согласован обратный импорт. Два независимо редактируемых «главных» экземпляра без правила сверки создадут расхождения.

## Ограниченная проба после выбора

С учётом предпочтения Кирилла первым кандидатом для короткой пробы является Excalidraw MCP App: проверить поддержку клиентом, затем цикл на 5–10 карточках. Если важнее постоянный локальный документ в браузере, следующий предмет согласования будет ограниченный прототип на Excalidraw SDK. Excalidraw+ имеет смысл оставить облачным запасным вариантом. Miro и FigJam технически подходят, но после уточнения предпочтения не являются основным направлением.

Проба должна проверить добавление карточек, точечное переименование и перемещение, сохранение ID, ручную правку с последующим чтением агентом, удаление с восстановлением, повторное открытие в новой сессии и экспорт редактируемого документа. Отдельно проверяем кириллицу, длинные подписи и сохранение чужих правок. Доступ к сцене по API не доказывает, что открытый браузер мгновенно показывает обновления.

Эта проба ещё не выполнена. Исследование подтверждает существование подходящих интерфейсов, но не измеряет удобство работы в Orca, задержки обновления, качество раскладки и поведение конфликтов на реальной доске.
