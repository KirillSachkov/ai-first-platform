# TypeScript и NestJS для backend

Принято с владельцем 30 октября 2026 года в задаче [«Каркас платформы: стек, модули, Docker Compose и проверки готовности»](https://github.com/KirillSachkov/ai-first-platform/issues/13).

Backend пишется на TypeScript под Node.js LTS с NestJS и Fastify-адаптером, frontend — отдельное SPA на React и TypeScript. Стек выбран по пригодности для проекта, а не по опыту команды: один язык на frontend и backend, общий подход к схемам данных на zod и официальный MCP SDK первого уровня для будущей точки входа агента.

## Рассмотренные варианты

- **C# и .NET 10.** Зрелая платформа для модульного монолита и сильная типизация. Отклонён: второй язык рядом с TypeScript-frontend, отдельный инструментарий и отдельные схемы контрактов.
- **Go.** Простая эксплуатация и быстрый старт. Отклонён: меньше готовых средств для модульной структуры, внедрения зависимостей и генерации OpenAPI из схем.
- **Kotlin и Spring Modulith.** Готовая поддержка модулей и событий между ними. Отклонён: тяжёлый стек для небольшой команды, MCP SDK для Java только второго уровня.
- **TypeScript без NestJS (Hono, Fastify напрямую).** Меньше слоёв. Отклонён: модулям нужны внедрение зависимостей и регистрация контрактов, которые пришлось бы писать самим.

## Последствия

- Внедрение зависимостей в NestJS опирается на явные токены (`@Inject(TOKEN)`): dev-запуск через tsx не выпускает метаданные типов декораторов.
- Контракт HTTP API описывается zod-схемами в слайсах и экспортируется в OpenAPI; frontend получает из него типизированный клиент.
