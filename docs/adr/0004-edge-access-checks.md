# Проверка входа на edge-слое до обращения к «Доступу»

Принято с владельцем 30 октября 2026 года в задаче [«Каркас платформы: стек, модули, Docker Compose и проверки готовности»](https://github.com/KirillSachkov/ai-first-platform/issues/13). Уточняет последствие [ADR-0001](0001-platform-access-ownership.md) о том, как «Доступ» учитывает активность учётной записи и действительность подключения.

Входящий запрос (HTTP, позже точка входа агента) принимает edge-слой вне модулей. Он проверяет сессию через «Сотрудников» или токен подключения через «Подключения агентов», затем активность владельца через «Сотрудников», затем получает у «Доступа» контекст разрешений и только после этого передаёт запрос фиче вместе с этим контекстом. «Доступ» не вызывает «Сотрудников» и «Подключения агентов», поэтому синхронный граф модулей остаётся ацикличным: «Сотрудники» → «Доступ» → «Проекты».

## Рассмотренные варианты

- **«Доступ» сам запрашивает активность учётной записи и подключения.** Буквальное прочтение ADR-0001. Отклонён: «Сотрудники» вызывает «Доступ» при прекращении доступа администратора, и граф получает цикл.
- **Каждый модуль проверяет вход сам.** Отклонён: проверки расходятся между сценариями человека и агента.

## Последствия

- Требование модели сохраняется: без активной учётной записи и действующего подключения сведения не выдаются, и решение принимается по актуальным данным источников истины на каждый запрос.
- Endpoint фичи объявляет нужный доступ, edge его проверяет; фичи получают контекст запроса как входные данные и не вызывают проверки входа сами.
- Endpoint без объявленного доступа отклоняется.
