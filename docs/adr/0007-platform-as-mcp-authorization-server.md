# Платформа как сервер авторизации MCP

Принято с владельцем 13 ноября 2026 года в задаче [«Согласовать техническое решение подключения и его проверки»](https://github.com/KirillSachkov/ai-first-platform/issues/56), решение 2А. Детали записаны в [итоге задачи](https://github.com/KirillSachkov/ai-first-platform/issues/56#issuecomment-6845974056), разделы «Подключение агента» и «MCP». Уточняет, чем владеют «Подключения агентов» по [ADR-0006](0006-first-version-modules.md).

Сервером авторизации для MCP служит сама платформа. Токены подключения выпускают «Подключения агентов» и на каждом запросе проверяют подключение по своей базе. Поэтому отзыв и истечение подключения действуют без окна.

## Как устроено

- **Маршруты.** Метаданные защищённого ресурса (RFC 9728) и заголовок `WWW-Authenticate` на ответ `401`, метаданные сервера авторизации (RFC 8414), `authorize`, `token`.
- **Согласие.** `authorize` требует веб-вход. Экран согласия показывает клиента и сотрудника. Код выдаётся только с PKCE `S256` и только на адрес `127.0.0.1` машины сотрудника. Порт при сравнении адреса не учитывается (RFC 8252). Ввод кода с устройства не используется.
- **Регистрация клиента.** CIMD (OpenCode выбирает его сам) и заранее зарегистрированный клиент. Динамической регистрации (DCR) нет: в редакции MCP 2026-07-28 она устарела. Сама платформа работает по редакции протокола 2025-11-25, это настройка OpenCode по умолчанию.
- **Токены подключения.** Непрозрачные, в базе лежит только SHA-256. Токен доступа живёт 15 минут. Токен обновления меняется при каждом обновлении, повторное использование старого токена обновления получает отказ.
- **Токен провайдера.** При согласии платформа получает у провайдера его токен обновления с `offline_access` и хранит его зашифрованным. При каждом обновлении токена подключения она сначала обновляет токен у провайдера. Так подключение сотрудника, которого провайдер перестал пускать, останавливается не позже чем через 15 минут. Тайм-аут обращения к провайдеру: 3 секунды.
- **Владение.** OAuth-клиенты, коды, токены подключений и токены провайдера для подключений принадлежат «Подключениям агентов». Провайдер вызывается через порт модуля.

## Открытый вопрос

Отзывать ли всё подключение, когда старый токен обновления подключения используют повторно. OpenCode обновляет токены параллельно, поэтому вопрос решит владелец по прогону чек-листа OpenCode до реализации подключения.
